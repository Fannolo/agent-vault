# Deployment, authority and proof plan

## Module map

| Owner | Contains | Allowed dependencies |
|---|---|---|
| Core/Broker | approval, reservations, live authority, operation lifecycle, result retention | Contracts, Approval, small credential format parser |
| Contracts/IPC | closed public read/admin statuses, frames and challenge DTOs; peer authentication | Foundation/Security; no Core or host-secret DTOs |
| BrowserHostProtocol | private start/stop/fixed workflow and challenge DTOs | Foundation, credential parser; imported only by daemon and host |
| BrowserHost executable | process launch, private pipe protocol, QEMU lifetime, limited egress and guest result validation | host protocol/runtime; no Core/Keychain |
| Linux guest worker | fixed recipes, allowlist, challenge DOM classification, Chromium CDP pipe, screenshot/input translation | pinned Chromium; no policy database |
| AppSupport | protected approval + cropped raster view/input, operation list | public Contracts/IPC; no Core, BrowserHost, WebKit |
| Runtime/installer | dedicated UID, root-owned image/binaries, digest pins, resource limits | existing runtime security checks |

Delete old WKWebView production path and HumanContinuationView when composed fixture parity exists; port hostile-site cases to new host. Do not leave two production browser engines or link Browser into the app to make its existing NSView fit. Preserve the fixture site as a browser-independent input corpus.

## Actual process/storage topology

System LaunchDaemon Broker (`_agentvault`) authenticates and starts a BrowserHost child under the same private UID. Host creates operation-private 0700 directory under protected runtime storage; only root-owned installed absolute paths may be launched. Verify each path component and file ownership/no symlinks, validate signed host code and a release manifest covering QEMU/kernel/read-only guest image. No global installations, Chrome profile changes, user login accounts, DNS changes, firewall changes, screen-recording or Accessibility permission are required during development.

QEMU is a private signed executable built without Cocoa/SDL UI dependency for the production configuration. Use TCG rather than depending on Hypervisor entitlement; required JIT signing is measured, not assumed. Command configuration includes `-display none -monitor none -serial none -nic none`, read-only root image, fixed memory/CPU caps, no shared directory/virtiofs/9p/device passthrough/QMP/VNC/SPICE. A private virtio-serial character device transports framed worker messages over a host-owned inherited channel (or AF_UNIX socket inside the private 0700 directory). Use one VM per operation; terminate it after final result. Linux root mounts tmpfs for browser profile and scratch, disables swap/core dumps, starts guest worker and browser as unprivileged dedicated guest UID with Chromium sandbox enabled. Guest secrets never enter argv/environment/logs/disk image; transport them after worker handshake over the private channel. Password fields are cleared by fixed recipes after successful login submission before human surface becomes eligible. No cookies are exported or persisted across operations.

No guest NIC means browser cannot reach host loopback, LAN, metadata addresses, DNS, UDP/WebRTC or internet directly. A guest loopback HTTP CONNECT proxy carries bounded encrypted TCP tunnel chunks over the private channel. Host maps a small compiled destination enum to reviewed DNS hostname/443, rejects unresolved/private/link-local/multicast destinations and pins each chosen address for that tunnel. It never accepts a caller-supplied arbitrary host. Browser validates ordinary site TLS; no TLS interception or trusted CA installation. Host destination allowlist contains only recipe origins. Guest Chromium interception separately enforces origin/path/frame/redirect/request-kind policy, including service worker and popup denial. App/MCP cannot access this tunnel or select its destinations. Host validates guest channel bytes as untrusted. A compromised allowed origin remains in the stated trust limit; TLS tunnel restriction alone does not enforce URL paths.

This is implementable topology, not tested software. QEMU documentation supports no-display command-line operation and NIC removal. It is still necessary to build and test the exact signed macOS binary under `_agentvault`; no production proof follows from the command example.

## Human continuation without transferring session ownership

A broker approval pending ID expires after at most 120 seconds. Once approved and resumed it is consumed transactionally with the single attempted-call reservation. Only then does browser execution start. A browser pause creates an independently typed OperationID and challenge epoch; its first-pause deadline is min(grant expiry, pause start + 600 seconds). Repeated classification or opening/closing the viewer never extends that deadline.

Human app lists browser operations via authenticated admin channel. Opening a challenge needs a fresh protected-key intent binding operation, current challenge epoch and current human connection. Broker checks authority and asks Host for challenge-only raster. Lease is bound to that authenticated XPC connection, not a reusable bearer credential; reconnect requires a fresh signed intent. Only one viewer per operation. Frames carry monotonically increasing frame IDs. Inputs are bounded coordinates, finite key codes, and short text only in a recognized challenge input. Inputs must refer to a recent matching frame and current page epoch; Host rejects input if DOM has navigated or crop is no longer challenge-only. Check exact page/iframe origin/path and challenge state before each frame/control; mask neither arbitrary content nor credentials by heuristic. If known challenge-only display cannot be established, fail with unsupported_challenge. Fixed Chrome screenshot/input calls are entirely private implementation details.

Frame crop and pointer event mapping support visual CAPTCHA challenges on reviewed origins. Control tab movement stays within approved challenge elements; browser shortcuts, file upload, arbitrary text entry elsewhere, clipboard, password managers, client certificates and WebAuthn native prompts are unsupported. CAPTCHA remains performed by the person; worker never solves it. Finish causes bounded fixed classification, not generic DOM read. Successful classification tears down browser before making the small typed profile ready for the originating client.

An agent sharing the human UID may observe the user's screen or manipulate UI if separately granted powerful OS accessibility rights. Signed XPC alone does not establish physical human intent for every click. The existing protected-key user-presence boundary gates viewer creation; this design does not claim defense against fully compromised human UI. Stronger per-event human proof would need a different trusted input device/UI trust model.

## Lifecycle and concurrency rules

1. Before reservation, preserve existing account/client/grant/action checks and approval requirement. Reservation transaction increments attempted count and consumes approval exactly once, records operation binding/credential generation, and establishes `starting` state. Duplicate approval resume returns its existing operation or terminal status, never a second browser. An initial run without idempotency key remains a new attempt as today; one-active-operation-per-account rejects concurrent requests before budget reservation.
2. Credential load may block. Recheck the exact client/account/action/grant tuple, lifecycle active, credential generation and grant expiry after it returns and immediately before dispatch. Do not require callsUsed < limit on continuation: the reserved last permitted attempt is still allowed.
3. Broker actor can reenter at every await. Bind a broker epoch plus operation epoch to each outbound host command; late replies from destroyed/replaced sessions cannot create a new pause/result. Apply reply only if live state remains the expected starting/awaiting/completing state and authority still holds. Host start racing cancellation must destroy the newly created child; a tombstone prevents late start from reviving it.
4. `awaitingHuman` records an audit of waiting, never `completed`. Poll is read-only, rechecks exact caller and live authority, returns running/waiting/typed ready. Human cannot dispatch another service or choose a new account/grant.
5. Revoke client/grant, rotate/delete account, expired grant, pause deadline, cancel, unreadable state and host failure all mark terminal first, invalidate leases, and destroy applicable Host operations. Scan the bounded operation table by client/grant/account; operation ID is never relabeled as grant/account ID. Timeouts run independently of polls. Retain operation grant references during grant pruning until terminal retention ends.
6. After successful host classification, tear down first. Recheck authority and account generation again before committing ready. Recheck once more on each agent poll before output. Keep ready results only in memory for min(60 seconds, grant expiry), then expire. Retry polls within retention return the identical bounded result; they never reload credentials or spend budget. Terminal failures remain briefly for deterministic retries.
7. Journal stores attempt/binding/status but no credentials/cookies/raster/profile. Broker restart changes epoch, marks interrupted operations unavailable and destroys previous process tree before accepting requests. Attempted counters are never refunded. BrowserHost exits its VMs on broker connection EOF; watchdog enforces hard operation/pause deadline even if the broker disappears. Reconnected host never resumes a previous browser profile. Host crash yields unavailable and no automatic credential redispatch.
8. Separate read/admin/raster/egress quotas. Raster requests never hold Core actor while waiting for bytes; max frame 1024x768 RGBA, 5 frames/sec, 16 operations total with lower configurable browser cap, capped input/tunnel queues. Destroy/control lane has priority. Do not let request flood delay revocation or protected approval.

## Resolve current contract disagreements in one unit

- Add distinct `github_web_profile` payload with bounded validated `login` and optional positive `userID`. Keep API `GitHubProfile.id` required. Never synthesize zero or coerce absent ID. Validate returned login against enrolled username where provider semantics permit; document this does not solve hostile allowed-origin leakage completely.
- Closed `status` enum (`complete`, `approval_required`, `running`, `human_step_required`, `failed`) plus closed failure reason enum; no `failed:<code>`. Update Core translation, exact-key WireCodec, bridge acceptance and serialization tests together.
- A common browser credential parser is authoritative at enrollment and rotation: <=4096 UTF-8 bytes, exactly username/LF/password according to current format. Retain 8192 only as the outer IPC envelope/other-service ceiling. Enforce service-specific parsing before any state/secret write; same parser in host. UI derives service bounds from shared schema instead of copying them.
- Approval resume and browser poll/cancel are separate methods and MCP tools. UI labels them explicitly. Remove unused ambiguous humanStepRequired UUID conversion from old BrowserOutcome.

## Verifiable rollout units

1. **Smallest unit:** Core reservation/operation state with deterministic fake executor and clock. Tests pause, grant-last-attempt continuation, revoked-before/after credential load, cancelled-during-start, wrong client poll, host late reply, rotation/deletion, 120-second approval vs 600-second pause, output expiry and restart. Required existing `swift test` and `scripts/verify-mcp.py` when parent implements Core/MCP.
2. Closed public/private DTO codecs, service-specific credential validation, and dedicated read/admin methods. Fuzz oversized/unknown-key/unknown-enum/wrong-epoch frames; dependency check ensures App/Bridge cannot import Core/private protocol.
3. Synthetic guest fixture worker with a real private host child and no browser: exercise authentication, framing, cancellation, crash and pixel limits. Use scratch namespace, no Keychain or installed daemon. This proves mechanics, not UID isolation.
4. Build immutable guest and rootless scratch Host launch. Real Chromium via private pipes logs into synthetic HTTPS fixture, pauses on MFA, receives fake-human code via same public admin raster/input methods, reads typed profile, and proves cookie/profile teardown. Fixture transport permits only its separately compiled test origin; no production switch takes arbitrary destinations or loopback exceptions. Verify forbidden navigation/subresource/iframe/download/popup/permission/redirect and oversized profile cases; verify no guest NIC/direct egress. Run same case with CAPTCHA clicks performed by test driver over synthetic challenge, not a real CAPTCHA.
5. Full **Broker → private Host → real browser → human challenge API → typed MCP poll** fixture using an ephemeral state store and fake secret store, separate processes, synthetic identities. Include host kill during pause, human lease replay, human disconnect, grant revoke while frame pending and during final classification. Assert exact attempted count 1 and one completion audit. This is the minimum integrated feature test; isolated host success is insufficient.
6. Build signed review bundle under existing Bite identity with all new executable roles and immutable image manifest covered; retain third-party licenses/source obligations. Do not re-sign external dependencies blindly with overbroad entitlements. Produce installer dry-run plan, dependency graph report and proof manifest locally. Actual publisher use remains parent's authorized release workflow.
7. In a dedicated disposable macOS test machine/VM, install `_agentvault` service and perform kernel UID, code-signing, no-GUI, file ACL, private-pipe, debugger/task-port denial, child sandbox, resource limits, crash cleanup, protected human-key presence and egress checks. Confirm default browser and every existing user profile/config unchanged. Repeat arm64/x86_64 targets claimed supported. Do not represent same-UID fixture as this gate.
8. Validate exactly one reviewed real GitHub web workflow using explicitly authorized synthetic account and real human challenge, with exact origin/selector contracts. Document provider limitations; enable browser service only for releases whose topology and workflow gates pass. Native signing/notarization and protected-key provisioning gates remain separately measured; model review does not close them.

Units 1–6 are independent implementation work even if installed OS proof or real-site verification cannot run in the current environment. No placeholder `BrowserUnavailable` adapter counts as complete integration.

## Sources and confidence

Inspected local Core Domain/Broker, package graph and AGENTS, and all provided grounding (source checkpoint 425c6af, docs 7e25512). Grounding is stronger than naming files; its linked original code establishes the missing production seams. Design/proof steps above are proposals, not observations.

- [Chrome Headless documentation](https://developer.chrome.com/docs/automation-and-testing/headless): documents unified headless platform windows, Linux/macOS invocation and standalone headless-shell. Does **not** establish private-UID WindowServer-free macOS execution.
- [Chrome remote debugging change](https://developer.chrome.com/blog/remote-debugging-port): pipe/port debugging is constrained for default data directories; this design always uses a unique owned tmpfs profile and never touches a real profile.
- [QEMU invocation](https://www.qemu.org/docs/master/system/invocation.html): documents TCG, display-none/nographic and NIC-none. This supports proposed topology, not performance, signing or installed-platform proof.
- [Chromium DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/): internal Page screenshot, Input dispatch and Fetch request interception are implementation building blocks only. Public interfaces expose none of CDP, selectors, URLs or evaluation strings. Pin the actual protocol schema to the bundled browser version, not moving `tot`.

## Red-flag screen

No public raw transport or browser-framework types; no dual WK/Chromium backend; no app Core dependency; no policy state written by host; fixed recipe only in guest worker; runtime derives install hashes from signed manifest. Host relay duplicates only origin destination enforcement as deliberate defense-in-depth; derive both guest and host allowlist from one reviewed recipe specification. UI never synchronizes authority. Three-owner call chain is meaningful: Broker authorizes, Host isolates, worker constrains browser. Guest appliance complexity is substantial, which is why a *proved* native dedicated-UID headless runner should win later synthesis on cost while retaining these contracts.
